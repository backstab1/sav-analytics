# Golden-набор статистики

`statistics_reference.json` содержит численные эталоны, рассчитанные независимо от
Python-кода приложения. Воспроизводящий скрипт `statistics_reference.R` использует
только Base R и печатает результаты pooled two-sided z-test, unpooled Wald CI и
Welch t-test с исходными выборками из JSON.

Используемые независимые примитивы описаны в официальной документации R:
[`pnorm`/`qnorm`](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/Normal.html)
и [`t.test` с Welch–Satterthwaite df](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/t.test.html).

Проверка выполняется так:

```text
Rscript tests/golden/statistics_reference.R
pytest tests/test_golden_statistics.py
```

`pipeline_statistics.sha256` имеет другую роль: это регрессионный отпечаток полного
`statistics.txt` после замены динамического времени на `<TIMESTAMP>`. Он гарантирует,
что ни одна строка аудита не изменилась незаметно, но сам по себе не является
независимым статистическим источником. Обновлять этот SHA допустимо только после
проверки чисел по независимому reference и осознанного просмотра изменения формата.

## Как обновлять

Главный риск этого набора в том, что `Rscript` не запускается в CI: тесты сравнивают
Python с уже зафиксированным `statistics_reference.json`. Поэтому упавший
golden-тест чинится только одним из двух способов:

1. **Ошибка в Python.** Чинить код, JSON не трогать. Это случай по умолчанию.
2. **Сознательное изменение методики.** Сначала правится `requirements.md`, затем
   `statistics_reference.R`, затем скрипт **действительно перезапускается**
   (`Rscript tests/golden/statistics_reference.R`), и только его вывод попадает в
   JSON. В блоке `provenance` обновляются `reference_locked_on` и версия R.

   Числа переносятся разбором напечатанного R, а не набором с экрана: скрипт
   печатает `dput`, значения вынимаются из него программно. Набранное руками
   число — это уже не эталон, а совпадение с чьей-то внимательностью.

Подгонять JSON под новый вывод Python нельзя ни при каких обстоятельствах: эталон,
который правят под код, перестаёт быть эталоном и делает весь набор бессмысленным.

Отдельно стоит помнить, чего этот набор не проверяет. R-скрипт написан вручную и
повторяет то же принятое методическое решение, что и Python. Он ловит арифметику,
опечатки и неверные формулы, но не подтверждает, что сам выбор метода правильный.
Обоснование выбора живёт в `requirements.md` и `docs/spss-conformance.md`.

При изменении формата аудита без изменения чисел достаточно обновить только
`pipeline_statistics.sha256`, предварительно убедившись `diff`-ом, что расхождение
ограничено ожидаемыми строками.

Текущий пакет покрывает z/Welch/Subgroup-Rest, приближённые weighted z/Welch,
NPS и CSAT balance, взвешенный balance с эффективными базами Киша, сравнение волн
по долям и по средним, MR `counted_value=2` и SPSS user-missing `99`.

Воспроизводимость проверена 10 августа 2026 года на R 4.6.1: скрипт запущен
заново, и все семь сопоставимых значений совпали с зафиксированными до 1e-12.
Восьмой кейс (`small_expected_frequency`) расходится намеренно — R считает
z-тест, а проект отказывается при ожидаемой частоте меньше 5, см. раздел 4.2
`docs/spss-conformance.md`.
