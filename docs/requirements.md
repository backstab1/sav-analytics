# Требования к sav-analytics

Статус: функциональные и методологические требования MVP согласованы. Фактическая
готовность и порядок реализации зафиксированы в [roadmap.md](roadmap.md) по текущему
`main`; этот документ остаётся контрактом требований, а не описанием готовых функций.

## 1. Пользователи и размещение

- Основные пользователи: аналитики внутренней команды.
- Язык интерфейса: русский.
- Формат: веб-приложение на внешнем сервере.
- Вход: логин и пароль.
- Все аналитики видят все проекты.
- Список проектов поддерживает поиск и сортировку.
- Приоритеты: точность, затем широта функций, затем скорость.

## 2. Проект и исходный файл

- Один проект содержит один основной SAV.
- SAV нельзя заменить после создания проекта; новый файл означает новый проект.
- В проекте хранится неизменяемая копия исходного SAV.
- Пользователь может скачать исходный SAV.
- В проекте хранятся созданные Excel-отчёты.
- История отдельных действий не требуется.
- Размер массива: ориентировочно от 200 до 10 000 строк.

## 3. Импорт SAV

SAV является единственным источником данных и исходных подписей. Импорт JSON анкеты не поддерживается.

Необходимо читать:

- данные;
- имена и метки переменных;
- метки значений;
- форматы;
- системные пропуски;
- пользовательские missing values;
- measurement level;
- наборы множественных ответов, если они описаны в SAV.

После загрузки приложение показывает число строк и переменных, найденные метаданные, предполагаемые типы вопросов, множественные группы и предупреждения.

Кроме SAV принимаются таблицы CSV и TSV в кодировке UTF-8 или Windows-1251; разделитель CSV определяется по содержимому. Таблица при загрузке однократно преобразуется в SAV, по которому идут все расчёты, а загруженный файл хранится неизменным оригиналом и отдаётся при скачивании исходника. Заголовок столбца становится подписью переменной, имя переменной — допустимым для SPSS. Столбец, все непустые значения которого — числа, в том числе с десятичной запятой, становится числовым; текстовый столбец не более чем с 30 различными значениями — кодами с подписями в порядке первого появления; остальные остаются строками.

### 3.1. Источники подписей

Подписи формируются из метаданных SAV со следующим приоритетом:

1. Идентификатор вопроса — имя переменной SPSS (`Q1`, `Q5_1` и так далее).
2. Текст вопроса — variable label.
3. Подписи вариантов ответа — value labels.
4. При отсутствии label используется имя переменной или исходный код значения.

На экране структуры пользователь может изменить подпись для отчёта. Такая правка сохраняется как настройка проекта и не меняет исходный SAV.

Для каждого вопроса поддерживаются отдельные редактируемые поля:

- название вопроса для топлайна и содержания;
- пояснение или текст шкалы;
- подписи вариантов ответа;

Исходное имя переменной и код вопроса из SAV не редактируются. Для группы множественного ответа интерфейс может показывать общий код, например `Q5`, но исходные переменные `Q5_1...Q5_n` сохраняют свои имена.

Название вопроса по умолчанию полностью совпадает с variable label. Приложение не пытается автоматически сокращать или переформулировать его. Если label отсутствует, используется код вопроса. Пользователь может вручную изменить название для отчёта.

Для множественного ответа приложение пытается отделить общий текст вопроса от подписи каждого варианта. Если однозначно сделать это нельзя, пользователь подтверждает или исправляет общий заголовок и подписи вариантов.

## 4. Структура данных

Приложение автоматически предполагает тип каждой переменной. Пользователь может:

- изменить тип вопроса;
- создать или удалить группу множественного ответа;
- сгруппировать переменные вида `Q5_1...Q5_n`;
- разгруппировать ошибочно найденную группу;
- настроить представление множественного ответа, закодированного дихотомиями или категориями;
- исключить служебные переменные из отчёта.

Открытые вопросы не входят в стандартный топлайн, пока не закодированы.

### 4.1. Устройство экрана

Экран содержит четыре представления:

1. `Вопросы` — основной сгруппированный аналитический вид.
2. `Переменные` — плоский технический список столбцов SAV.
3. `Перекодировки` — созданные производные переменные.
4. `Исключённые` — открытые, служебные и вручную исключённые переменные.

Для каждого вопроса показываются код, подпись, тип, число исходных переменных, валидная база, пропуски, статус распознавания и включение в отчёт. Выбранный вопрос редактируется в боковой панели. Предпросмотр будущего блока топлайна в минимальную версию не входит.

Вопросы можно вручную сортировать перетаскиванием. Выбранный порядок используется в топлайне и содержании. Отдельной сущности `Раздел` нет: визуальные заголовки в топлайне являются названиями вопросов.

Название вопроса берётся из variable label без сокращения. Для multiple и matrix приложение пытается выделить общий заголовок из сходных подписей входящих переменных. Если общего названия определить нельзя, используется общий код вопроса, например `Q5`.

Массовая операция поиска/замены или очистки подписей не требуется.

### 4.2. Тип и роль

Физический формат данных отделён от аналитического типа и роли переменной.

Поддерживаемые типы:

- single choice;
- multiple choice в дихотомическом представлении;
- multiple choice в категориальном представлении;
- шкала;
- числовой показатель;
- ранжирование;
- матрица шкальных утверждений;
- открытый текст;
- служебная переменная.

Отдельная аналитическая поддержка даты и времени в минимальную версию не входит. Поля даты сохраняются из SAV как технические, но не используются в топлайне и конструкторе фильтров.

Отдельно задаётся роль: обычный вопрос, ID, вес, волна, фильтрующая/маршрутная или техническая переменная. В одном проекте может быть только одна переменная с ролью `Волна`; она должна иметь тип single choice.

Если SAV metadata и фактические значения конфликтуют, приложение использует наиболее вероятный аналитический тип по структуре значений и показывает предупреждение. Предположение сохраняется, пока пользователь его не изменит; статус `Не определено` автоматически не назначается. Вопрос, включённый в отчёт, с неподтверждёнными предупреждениями распознавания получает статус `Проверить` и учитывается в счётчике; сохранение вопроса подтверждает распознавание. Статус вычисляется из предупреждений и способа распознавания и отдельно не хранится.

Восстановление автоопределения выполняется для отдельного вопроса. Глобальная кнопка сброса всего экрана не нужна.

### 4.3. Шкалы

Для шкалы задаются допустимый диапазон и произвольные пользовательские группы, например `0–4 / 5–7 / 8–10`.

В топлайне сначала всегда показывается полное распределение по всем значениям шкалы. Под ним располагаются вычисляемые строки: среднее, Top-2 и другие включённые пользователем группы или показатели.

Стандартные агрегаты выбираются из выпадающего списка: `Top-1`, `Top-2`, `Top-3`, `Bottom-1`, `Bottom-2`, а также `Пользовательская группа`. Статистические группы могут пересекаться. В отличие от них, категории новой перекодированной переменной пересекаться не могут.

### 4.4. Multiple

Приложение автоматически распознаёт группы из SPSS multiple-response metadata, последовательностей имён и сходства подписей. Пользователь может исправлять состав найденной группы, добавлять или исключать совместимые переменные и разгруппировывать её.

Создание произвольного multiple из любых несвязанных переменных не поддерживается. Общий код группы не переименовывает исходные переменные SAV.

### 4.5. Матрицы

Приложение по умолчанию предлагает матрицы из переменных со сходными именами и подписями и с одинаковой шкалой. Пользователь может вручную собрать матрицу из любых переменных с одинаковой шкалой. Переменная с отличающейся шкалой исключается из матрицы.

Для каждого утверждения матрицы в топлайне сначала показывается полное распределение, затем среднее и выбранные агрегаты шкалы.

### 4.6. Ранжирование

Поддерживаются обе распространённые структуры: отдельная переменная на вариант с записанным местом и отдельная переменная на место с записанным вариантом.

Ранжирование является строгим: одинаковые места не допускаются. Частичное ранжирование в минимальной версии не поддерживается. По умолчанию в топлайне выводятся распределение по местам и среднее место.

### 4.7. Отмена действий

Экран поддерживает отмену последних пользовательских изменений через кнопку `Отменить` и сочетание `Ctrl+Z`. Это локальная отмена действий в текущей рабочей сессии, а не журнал версий проекта.

### 4.8. Пропуски и фильтровые вопросы

В рамках принятой модели респондент обязан ответить на каждый показанный ему вопрос. Поэтому наличие хотя бы одного отсутствующего значения автоматически означает, что вопрос задавался по фильтру. Дополнительное различение `не ответил` и `не был спрошен` не требуется, порог доли пропусков не применяется, ручное переопределение статуса Main/Filter не поддерживается.

Фильтровый вопрос включается одновременно в оба листа:

- в `topline_main`, где доли рассчитываются от общего Total массива;
- в `topline_filter`, где расчёты выполняются по валидной базе вопроса.

Для числовых фильтровых вопросов среднее, медиана, минимум, максимум, стандартное отклонение и стандартная ошибка рассчитываются только по фактически имеющимся значениям, в том числе на `topline_main`.

Код, которым в массиве обычным значением записан пропуск по ветке анкеты, пользователь может пометить как «не применимо». Перед сохранением показывается валидная база вопроса до и после пометки. Подписанная категория при любой частоте и неподписанный код, стоящий не менее чем у 10% валидной базы, помечаются только после явного подтверждения, что это пропуск, а не ответ; без подтверждения пометка отклоняется. Однажды подтверждённый код повторного подтверждения не требует.

### 4.9. Порядок и включение в отчёт

Исходный порядок вопросов соответствует порядку переменных в SAV. После объединения multiple или matrix весь блок занимает позицию первой входящей переменной. Пользователь может изменить порядок перетаскиванием.

По умолчанию в топлайн включаются single, multiple, шкалы, числовые вопросы, матрицы, ранжирования и закодированные открытые вопросы. Не включаются исходный открытый текст, ID, вес, переменная волны как самостоятельный вопрос и технические переменные.

### 4.10. Сохранение

Изменения сохраняются явным действием. Ни один редактор не имеет права потерять введённое молча: закрытие, переход в другой раздел, перезагрузка и уход со страницы при несохранённых изменениях сопровождаются выбором `Сохранить`, `Отменить изменения` или `Вернуться`. `Ctrl+Z` и кнопка `Отменить` работают только до ухода с экрана или обновления страницы; постоянная история изменений не хранится.

Автоматическое сохранение после каждого действия остаётся возможным развитием, но обязательным требованием не является: решение принимается отдельно вместе с индикатором состояния и поведением при конфликте ревизий. Прежняя редакция требовала autosave, которого в продукте никогда не было, и это расхождение дважды попадало в аудит.

## 5. Перекодирование

Перекодирование — обязательная часть минимальной версии. Особенно важна настройка возрастных групп.

Пользователь должен иметь возможность:

- создавать новую производную переменную, не меняя оригинал;
- объединять категории;
- задавать диапазоны числовой переменной, в том числе заготовкой по данным: группы равной численности (квантили) или равные интервалы; границы ставятся на точность данных, чтобы ни одно значение не выпало между группами, а совпадающие границы квантилей объединяют группы;
- задавать названия новых категорий;
- обрабатывать пропуски и значения вне диапазонов;
- использовать перекодированную переменную в баннерах, фильтрах и анализе.

Для одной исходной переменной разрешено создавать несколько независимых перекодировок и использовать разные варианты в разных баннерах и фильтрах.

Логическая переменная — производная переменная, категории которой заданы правилами конструктора условий (§7.1), а не кодами одной исходной переменной. Респондент получает категорию первого правила, которому он удовлетворяет; не удовлетворивший ни одному получает пропуск. Поэтому категории логической переменной не пересекаются, и она доступна в баннере, фильтрах и таблицах наравне с другими перекодировками. Правило логической переменной не может ссылаться на другую логическую переменную. Вопрос или перекодировку, на которые ссылаются её правила, нельзя удалить, пока связь не снята.

Формула — производная числовая переменная, вычисленная из переменных массива. Выражение допускает числа, переменные, знаки `+ − * /`, сравнения `= <> < <= > >=`, `AND`, `OR`, `NOT` и функции `SUM`, `MEAN`, `MIN`, `MAX` (по заполненным аргументам), `COUNT(значение, поля…)`, `IF(условие, да, нет)`, `ABS`, `ROUND`; имя переменной с недопустимыми знаками записывается в квадратных скобках. Пропуски обрабатываются по правилам SPSS: арифметика и сравнение с пропуском и деление на ноль дают пропуск, `AND` и `OR` трёхзначны. Формула опирается только на числовые переменные исходного файла, её имя уникально и после создания не меняется. До сохранения показывается, у скольких респондентов результат посчитан и у скольких пуст из-за каждого поля. Сохранённая формула становится числовым вопросом структуры и доступна в отчёте, таблицах, фильтрах, баннерах и перекодировках; исходный SAV не меняется, формула пересчитывается при каждом расчёте. Формулу нельзя удалить, пока на неё ссылаются баннер, фильтр, перекодировка или вес отчёта.

Проект выгружается в SAV с производными переменными: исходные столбцы с их подписями, подписями значений и объявленными пропусками, затем формулы (числовые столбцы), перекодировки и логические переменные (коды категорий с подписями) и рассчитанные веса. Подпись одиночного вопроса, исправленная в структуре, заменяет подпись переменной. Исходный файл проекта при этом не меняется; совпадающее имя производной переменной получает числовой суффикс. Каждый записанный SAV перечитывается и сверяется по составу переменных; испорченный файл не отдаётся. Текстовые переменные длиннее 255 байт с похожими именами библиотека записи портит, поэтому в таком случае выгрузка объясняет причину и предлагает выгрузить SAV без этих переменных — их список пишется в заметку файла.

## 6. Баннеры

- Приложение предлагает демографические кандидаты: пол, возраст, доход, город и похожие переменные.
- Итоговый баннер пользователь собирает самостоятельно для каждого проекта.
- `Total` всегда является первым столбцом баннера, его нельзя удалить или переставить.
- В баннер можно добавлять single choice, переменную волны и категориальные производные переменные. Числовая переменная добавляется только после перекодировки в диапазоны. Multiple-response в дихотомическом представлении добавляется в баннер колонкой на каждый вариант: в колонку входят выбравшие этот вариант. Такие колонки пересекаются, поэтому внутри их блока сравнение выполняется только схемой подгруппа против остальных (или против Total, если так настроен отчёт); попарный тест между пересекающимися колонками не выполняется, пока не принят метод для зависимых выборок, и причина пишется в `statistics.txt`. Редактор баннера до построения отчёта показывает, у скольких респондентов колонки блока пересекаются.
- Одну исходную переменную можно добавить в баннер несколько раз, в том числе с разными перекодировками.
- Поддерживаются обычные и вложенные баннеры глубиной до двух уровней в минимальной версии.
- Вложение означает полное пересечение категорий двух переменных, например все комбинации `Возраст × Пол`; выбор отдельных пересечений не поддерживается.
- Первая переменная вложенного блока является внешней и определяет основной порядок столбцов. Например, блок `Пол → Возраст` выводится как `Мужчины 18–24`, `Мужчины 25–34`, `Мужчины 35–44`, затем `Женщины 18–24`, `Женщины 25–34`, `Женщины 35–44` и так далее.
- Категории внутри блока по умолчанию располагаются по кодам значений из SAV. Пользователь может изменить порядок перетаскиванием.
- Отдельную категорию можно отключить только в конкретном баннере, не создавая новую перекодировку. В том же списке категорий блока задаются порядок колонок и подпись колонки в этом баннере; рядом с категорией показана её база. Категории, появившиеся в данных после настройки, выводятся в конце, а скрыть все категории уровня нельзя.
- Категории с нулевой базой остаются доступными в настройках блока, но не выводятся в Excel.
- Категории с малой базой не исключаются из отчёта: их ячейки заливаются серым цветом.
- Порог малой базы проверяется по невзвешенному N, даже если результаты отчёта рассчитаны с весом.
- При достижении 50 столбцов приложение показывает неблокирующее предупреждение о ширине отчёта.
- Базы выводятся сверху в баннере.
- Пропуски баннерной переменной не образуют отдельную категорию и не входят в её подгруппы. При этом `Total` продолжает включать весь массив.
- Пользователь может выбрать переменную волны и сравниваемые значения внутри неё. В плавающем тесте каждая волна сравнивается с непосредственно предыдущей; дополнительно поддерживается режим сравнения всех волн с выбранной контрольной волной.
- В одной ячейке могут одновременно отображаться цвет сравнения с `Total` и стрелка изменения к волне.

### 6.1. Устройство экрана

Экран состоит из трёх основных областей:

1. Каталог переменных с поиском и предложенными демографическими переменными.
2. Полотно баннера с зафиксированным `Total` и карточками добавленных блоков.
3. Компактная сводка: число итоговых столбцов, минимальная база и количество групп с малой базой.

Предложенные переменные не добавляются автоматически: окончательный выбор всегда делает пользователь.

В карточке блока доступны название, исходная или перекодированная переменная, категории и их порядок, вложенность, число создаваемых столбцов, базы и удаление блока. Название по умолчанию берётся из variable label и может быть изменено для отчёта.

Для всего баннера включаются два единых режима: сравнение подгрупп с `Total` и попарное сравнение подгрупп между собой. Настройка применяется ко всем блокам баннера. Во вложенном блоке каждое итоговое пересечение является самостоятельной подгруппой: при включении соответствующих режимов оно сравнивается с `Total` и со всеми остальными пересечениями этого блока. Между категориями несвязанных блоков сравнения не выполняются.

Столбцам присваиваются сквозные буквенные идентификаторы: `Total = A`, далее `B`, `C`, `D` и так далее. Эти идентификаторы используются в примечаниях со значимыми попарными различиями.

Уровень доверия задаётся отдельным полем, по умолчанию `95%`; допускается произвольное корректное значение. Поправка Bonferroni включается отдельным переключателем и никогда не применяется без явного выбора пользователя. При включении поправка рассчитывается отдельно для каждой строки результата внутри каждого логического блока, а не одновременно для всех тестов отчёта.

### 6.2. Перекодировки на экране баннера

Правила перекодировки не должны постоянно занимать место на основном экране. В меню переменной пользователь выбирает существующую перекодировку либо команду создания новой. Создание и редактирование открывается в отдельном модальном окне достаточного размера, а не в маленьком выпадающем меню.

Модальное окно содержит исходную переменную, название производной переменной, правила объединения категорий или числовые непересекающиеся диапазоны, а также проверку покрытия значений и получающихся баз. Границы диапазонов отображаются однозначно, например `18–24` и `25–34`. Для каждого наблюдаемого значения, не попавшего в диапазоны, пользователь обязан явно выбрать действие: исключить его либо поместить в категорию `Другое`.

После сохранения перекодировка становится проектной производной переменной и доступна на экране структуры, в других баннерах и в фильтрах наряду с исходными переменными. Исходная переменная не изменяется. Если используемая перекодировка редактируется, приложение предупреждает об обновлении всех связанных мест и предлагает альтернативу `Сохранить как новую`. Удалить перекодировку, пока от неё зависят баннеры или фильтры, нельзя.

### 6.3. Автоматические рекомендации демографии

Приложение детерминированно ищет демографические переменные по имени переменной, variable label и value labels SAV. Используется встроенный русско-английский словарь и правила для пола, возраста, дохода, занятости/работы, образования, города и наличия детей. Внешний AI-сервис и отправка подписей за пределы приложения не используются.

Найденные переменные являются только рекомендациями и никогда не добавляются в баннер автоматически. Если на одну демографическую роль найдено несколько кандидатов, показываются все в порядке внутренней уверенности распознавания, но основание и числовая оценка уверенности пользователю не выводятся.

Числовой возраст нельзя добавить в баннер напрямую: приложение предлагает создать и подтвердить перекодировку. Стандартное предложение диапазонов — `18–24 / 25–34 / 35–44 / 45–54 / 55+`; пользователь может изменить его до сохранения.

Переменная с большим числом категорий, например город, остаётся в рекомендациях с предупреждением о ширине баннера. Переменная, заполненная менее чем у 80% массива, также показывается, но с предупреждением о неполной базе.

Из рекомендаций автоматически исключаются ID, вес, волна, технические, multiple-response и открытые текстовые переменные. Пользователь может вручную отметить любую single или перекодированную категориальную переменную как демографическую рекомендацию независимо от результатов автоматического поиска.

## 7. Базы и фильтры

Базовый Excel-отчёт содержит три обязательных листа:

1. `Содержание`;
2. `topline_main`;
3. `topline_filter`.

Лист `Correlations` и будущие листы дополнительных методов включаются и отключаются пользователем при настройке отчёта.

Правила:

- `topline_main` включает все вопросы, в том числе задававшиеся по фильтру.
- Доли на `topline_main` по умолчанию считаются от общего N массива.
- `topline_filter` содержит только вопросы, задававшиеся не всем.
- На `topline_filter` расчёты выполняются по валидной базе вопроса.
- Системные и пользовательские пропуски исключаются; их количество доступно пользователю.
- Для множественного выбора базой являются все респонденты, которым вопрос был задан, включая не выбравших ни одного варианта.
- Для дихотомического multiple-response набор нулей во всех вариантах означает, что респондент получил вопрос и ничего не выбрал; пропуски во всех вариантах означают, что вопрос ему не задавался.
- Сложные фильтры создаются через интерфейс, без написания синтаксиса.
- По умолчанию общий фильтр отчёта отсутствует, а `Total` равен всему массиву.
- Общий фильтр отчёта ограничивает все его результаты: `topline_main`, `topline_filter`, корреляции и статистические тесты.
- В одной конфигурации отчёта может действовать не более одного общего фильтра; один Excel не разбивается на дополнительные листы для нескольких аудиторий.
- Проект может хранить несколько именованных правил, которые повторно используются как фильтры отчёта или базы вопросов.
- Пользовательская база назначается только одному вопросу за одну операцию. Массовое назначение одной базы нескольким или всем вопросам не поддерживается.
- У одного вопроса одновременно может быть только одна пользовательская база.
- Явно назначенная пользовательская база заменяет стандартный знаменатель `Total` для этого вопроса и на `topline_main`.
- Для автоматически фильтрового вопроса на `topline_filter` итоговая база равна пересечению валидной базы вопроса, пользовательской базы и общего фильтра отчёта.
- В каждом столбце баннера итоговая база вопроса равна пересечению пользовательской базы, подгруппы баннера и общего фильтра отчёта. В столбце `Total` такого вопроса показывается N пользовательской базы в пределах общего фильтра отчёта.
- Назначенная база действует для вопроса одновременно на `topline_main` и `topline_filter`; правила знаменателя каждого листа применяются после пересечения с этой базой.
- Применённая пользовательская база отображается под названием вопроса и отмечается в содержании Excel.

Числовые показатели фильтрового вопроса рассчитываются по валидным числовым значениям, даже когда доли на `topline_main` считаются от общего Total.

### 7.1. Устройство экрана

Экран состоит из трёх основных областей:

1. Список сохранённых именованных фильтров и баз.
2. Визуальный конструктор условий.
3. Сводка получающейся выборки и вопрос, к которому применяется база.

Доступные операции зависят от типа переменной и включают: `равно`, `не равно`, `входит в список`, `не входит в список`, `больше`, `меньше`, `между значениями`, `заполнено` и `пропущено`. Исходные и перекодированные переменные доступны на равных условиях. Открытые текстовые поля и даты в конструкторе фильтров не используются.

Multiple-response разрешён как источник условия фильтра, хотя не поддерживается в баннере. Для него доступны операции: выбран конкретный вариант, выбран хотя бы один из перечисленных, выбраны все перечисленные и не выбран ни один из перечисленных.

Условия объединяются операторами `И` и `ИЛИ`; поддерживаются логические группы с вложенностью до двух уровней. Рядом с каждым условием и для всего правила показываются невзвешенный N и доля подходящих респондентов. Если включён вес, дополнительно показывается взвешенная база, но порог малой базы по-прежнему проверяется по невзвешенному N.

Пропуски доступны как единая категория `Любой пропуск` и раздельно как системные и пользовательские пропуски SAV. Операции отрицания, например `Возраст ≠ 25`, не включают пропущенные значения автоматически; для этого пользователь явно добавляет условие через `ИЛИ`.

Перед сохранением приложение показывает собранное правило обычным текстом, например `Возраст 18–34 И (Москва ИЛИ Санкт-Петербург)`.

Пустая итоговая база блокирует продолжение и сопровождается указанием условия, после которого выборка обнулилась. Малая ненулевая база не блокирует работу: приложение показывает предупреждение, а соответствующие результаты в Excel заливаются серым.

Сохранённое правило можно копировать. При редактировании уже используемого правила приложение предупреждает, какие связанные настройки обновятся, и предлагает `Сохранить как новую`. Удаление используемого фильтра или базы блокируется, пока пользователь не снимет все связи либо не выберет замену.

## 8. Настройка и генерация отчёта

Все настройки отчёта размещаются на одном экране без дополнительных шагов. В верхней части показывается сводка: исходный SAV, число респондентов, выбранный общий фильтр, состав баннера, число включённых вопросов и статус веса. Все вопросы, включённые на экране структуры, автоматически попадают в отчёт и повторно здесь не выбираются.

На экране доступны:

- переключатели необязательных аналитических листов, включая `Correlations`;
- включение веса и выбор переменной с ролью `Вес`; по умолчанию вес выключен;
- глобальный уровень доверия, переключатель Bonferroni и порог малой базы;
- глобальный переключатель вывода p-value, по умолчанию выключенный;
- наборы выводимых показателей по типам вопросов.

При включённом весе по умолчанию показываются и невзвешенный N, и взвешенная база. Доли и показатели рассчитываются с весом, а статистические значимости — с использованием эффективных баз. Нельзя подставлять обычный невзвешенный N в формулу для взвешенных долей.

Наборы показателей настраиваются сразу для всего отчёта: доли и базы для single/multiple; распределение, среднее и выбранные Top/Bottom для шкал; среднее, медиана, минимум, максимум, стандартное отклонение и стандартная ошибка для numeric; распределение мест и средний ранг для ranking. Индивидуальные настройки вопроса, включая NPS и специальные группы шкалы, задаются на экране структуры; экран генерации показывает их сводку без редактирования.

Перед запуском выполняется проверка конфигурации. Пустая активная база вопроса, пустой общий фильтр отчёта и непригодная переменная веса являются ошибками и блокируют генерацию. Малые базы, нулевые категории баннера, слишком широкий баннер и вопросы с неподтверждённым распознаванием являются предупреждениями и не блокируют запуск. Отсутствие подписи вопроса предупреждением не считается: используется код переменной по ранее установленному правилу.

Имя Excel-файла формируется автоматически как `<Название проекта>_<дата-время>.xlsx` и перед запуском не редактируется. Excel и `statistics.txt` скачиваются двумя отдельными кнопками, ZIP-архив не создаётся.

Генерация выполняется в фоне с индикатором прогресса; пользователь может покинуть экран и вернуться позже. После завершения показываются время расчёта, количество листов, вопросов и предупреждений, а также кнопки скачивания. Просмотр Excel в браузере в минимальную версию не входит.

Сформированные отчёты сохраняются в проекте как неизменяемые версии с датой, автором и использованной конфигурацией. Новая генерация не перезаписывает старые файлы.

### 8.1. Показатели

Настройки по умолчанию:

- доли без знака `%`, округление до целого;
- базы целыми числами;
- среднее с одним знаком;
- для шкал: распределение по баллам, среднее и Top-2;
- для числовых переменных: среднее, медиана, минимум, максимум, стандартное отклонение и стандартная ошибка.

Дополнительные показатели включаются и отключаются пользователем.

Для шкал и элементов матриц пользователь отмечает, какие строки выводить: распределение, среднее, `Top-2`, `Bottom-2`; для числовых переменных — любое непустое подмножество среднего, медианы, минимума, максимума, стандартного отклонения и стандартной ошибки. Порядок строк не зависит от порядка отметок. Число знаков после запятой задаётся отдельно для долей (0–2) и средних (0–3) и меняет только числовой формат ячейки. Строки базы в набор не входят и выводятся всегда. NPS и CSAT выводятся полностью независимо от набора. Готовые наборы показателей лишь проставляют отметки; набор узнаётся по совпадению отметок и отдельно не хранится. В минимальной версии должны поддерживаться NPS и CSAT. Конструктор CSI переносится в одну из версий после запуска основного продукта.

P-value по умолчанию не выводится в топлайн, но может быть включён настройкой. Полные расчёты сохраняются в `statistics.txt`.

#### NPS

NPS назначается только шкале `0–10`. Используются неизменяемые стандартные группы: критики `0–6`, нейтралы `7–8`, промоутеры `9–10`; `NPS = доля промоутеров − доля критиков`. Ручное изменение границ не поддерживается.

В топлайне выводятся полное распределение шкалы, три группы и отдельная строка NPS; среднее для такого вопроса не выводится. Распределение и группы на `topline_main` считаются от Total, а на `topline_filter` — от валидной базы по общим правилам листов. Все доли и NPS отображаются без знака `%`.

Для сравнения NPS между независимыми группами используется специализированный двусторонний z-тест разности NPS. Для каждой группы `Var(NPS) = [p_promoters + p_detractors − (p_promoters − p_detractors)²] / n_eff`, после чего разность двух NPS делится на объединённую стандартную ошибку. Без веса вместо `n_eff` используется обычная база; с весом — эффективная база Киша.

#### CSAT

CSAT назначается только шкале `1–5`. Используются неизменяемые группы: неудовлетворённые `1–2`, нейтральные `3`, удовлетворённые `4–5`.

В топлайне выводятся полное распределение, три группы, строка `CSAT balance = доля удовлетворённых − доля неудовлетворённых` и отдельная итоговая строка `% удовлетворённых`. Несмотря на совпадение последней строки со строкой группы удовлетворённых, она сохраняется как явно обозначенный классический показатель CSAT. Все значения отображаются без знака `%`.

Распределение и показатели на `topline_main` считаются от Total, а на `topline_filter` — от валидной базы по общим правилам листов. Для сравнения CSAT balance применяется тот же специализированный z-тест разности двух долей и его дисперсия, что для NPS. Для сравнения `% удовлетворённых` применяется обычный двусторонний z-тест долей. Во всех взвешенных тестах используются эффективные базы Киша.

### 8.2. Структура Excel-топлайна

Обязательные листы называются строго `Содержание`, `topline_main` и `topline_filter`. Книга также содержит лист `Параметры`: SHA-256 исходного файла, ревизию конфигурации, версию приложения, баннер, текст общего фильтра, вес, настройки сравнений и волн и набор вывода — достаточно, чтобы воспроизвести расчёт без доступа к проекту. Первые три из этих сведений повторяются в шапке `statistics.txt`.

Верхняя часть каждого листа топлайна содержит многоуровневый баннер со строками: название блока, название подгруппы, буквенный идентификатор, невзвешенный N и, при включённом весе, взвешенная база. Взвешенная база отображается целым числом. Идентификаторы назначаются как в Excel: `A...Z`, затем `AA`, `AB`, `AC` и так далее. Верхние строки баннера и первый столбец закрепляются при прокрутке.

Заголовок вопроса содержит код и полный variable label, например `Q5. Какие марки вы знаете?`. Если label отсутствует, выводится только код без предупреждения и дополнительных пустых строк.

Общие правила строк:

- категории по умолчанию следуют порядку кодов SAV;
- для категориальной переменной пользователь может выбрать порядок `По коду`, `По возрастанию` или `По убыванию`; последние два режима сортируют варианты по точной неокруглённой доле в столбце Total, а при включённом весе — по взвешенной доле;
- при равных долях варианты дополнительно сортируются по коду SAV;
- для шкал и ranking сортировка по доле не применяется: сохраняется смысловой порядок значений;
- пропуски не выводятся отдельными строками;
- single содержит строки вариантов ответа;
- multiple содержит строки вариантов без строки `Итого`, поскольку сумма долей может превышать 100%;
- у одиночного выбора, шкалы, элемента матрицы и multiple в карточке вопроса задаются NET-группы: строка `NET: <название>` — доля тех, чей ответ входит в группу (у multiple — кто выбрал хотя бы один из её вариантов), от той же базы, что строки распределения, и с теми же тестами долей. NET-строки выводятся независимо от набора вывода, потому что принадлежат вопросу;
- шкала содержит полное распределение по возрастанию кода, затем среднее, `Top-N` по N максимальным кодам и `Bottom-N` по N минимальным кодам, где N от 1 до 3 задаётся настройкой отчёта и по умолчанию равно 2; специальные ответы в эти показатели и среднее не входят;
- numeric содержит отдельные строки среднего, медианы, минимума, максимума, стандартного отклонения и стандартной ошибки;
- ranking содержит распределение по местам, затем средний ранг;
- по настройке отчёта «N под долями» под каждой строкой долей выводится строка `<ответ>, N` — невзвешенное число давших этот ответ в колонке от той же базы, что доля; по умолчанию выключено;
- по настройкам «% по строке» и «% от общего» под долей выводятся строки `<ответ>, % по строке` — какая часть давших этот ответ приходится на колонку (в Total 100) — и `<ответ>, % от общего` — доля давших ответ и попавших в колонку от всей базы вопроса; обе считаются с весом отчёта от той же базы, что доля над ними, тестов значимости не имеют и по умолчанию выключены;
- шкала, матрица и числовой вопрос могут иметь свой набор выводимых показателей из набора своего типа; он заменяет набор отчёта для этого вопроса, а вопросы со своим набором перечисляются на листе `Параметры`;
- по настройке отчёта «Графики в книге» книга получает лист `Графики`: на каждое распределение вопроса — горизонтальный столбчатый график Excel, ряды которого — колонки баннера (не больше 12), а значения — ссылки на ячейки `topline_main`; по умолчанию выключено;
- между вопросами оставляется одна пустая строка.

Матрица выводится одним общим блоком вопроса. Каждый элемент матрицы является вложенным подблоком со своей подписью, полным распределением шкалы, средним, `Top-2` и `Bottom-2`. Агрегаты располагаются непосредственно под средним соответствующего элемента; отдельных сводных блоков внизу матрицы нет.

Результаты хранятся в ячейках как числовые значения Excel полной точности; требуемое округление задаётся числовым форматом, а не преобразованием в текст.

Лист `Содержание` разделён на области `topline_main` и `topline_filter`. Для каждого вопроса показываются код, название и ссылка на соответствующую строку. Фильтровый вопрос присутствует в обеих областях и имеет две отдельные ссылки на два листа.

Если невзвешенная база подгруппы ниже установленного порога, серым цветом заливается весь столбец этой подгруппы. При включённом выводе p-value значение и детали теста помещаются в примечание к ячейке, а не в дополнительные строки или столбцы.

## 9. Статистические сравнения

### 9.1. Доли

- Двусторонний z-тест двух пропорций.
- Каждый вариант multiple-response рассматривается как отдельный бинарный показатель `выбрал / не выбрал` и тестируется по тем же правилам долей.
- Top/Bottom-группы шкалы, категории NPS и другие пользовательские объединения значений также тестируются как доли.
- Уровень доверия по умолчанию: 95%, настраиваемый.
- Bonferroni включается отдельной настройкой.
- z-тест выполняется только тогда, когда все четыре ожидаемые частоты таблицы `2×2` не меньше 5. Ожидаемые частоты рассчитываются по объединённой доле при нулевой гипотезе отдельно для успеха и неуспеха в каждой из двух сравниваемых групп.
- Если хотя бы одна ожидаемая частота меньше 5, тест не выполняется. Автоматическая замена на точный или другой альтернативный тест не применяется; причина пропуска фиксируется в примечании к ячейке и в `statistics.txt`.
- При включённом весе доли рассчитываются по весам, а для приближённого z-теста используются эффективные базы Киша. Объединённая доля и ожидаемые частоты рассчитываются по взвешенным долям и эффективным базам сравниваемых групп. Если хотя бы одна ожидаемая частота меньше 5, тест не выполняется.
- Значения 0% и 100% сами по себе не запрещают тест: он выполняется, если обычные или эффективные базы и все четыре ожидаемые частоты удовлетворяют установленным ограничениям.

### 9.2. Средние

- Для независимых групп по умолчанию используется двусторонний t-тест Уэлча.
- При включённом весе используются взвешенное среднее, корректная взвешенная дисперсия и эффективные базы сравниваемых групп. Такой тест является приближённым и не заменяет полноценный design-based анализ стратифицированной или кластерной выборки.
- Тест средних применяется к шкалам и numeric. Медиана, минимум, максимум, стандартное отклонение и стандартная ошибка между группами не тестируются.

### 9.3. Subgroup и Total

Если подгруппа входит в Total, для теста строится непересекающаяся группа `Rest = Total − Subgroup`, после чего сравниваются Subgroup и Rest. В интерфейсе такое сравнение может называться `подгруппа vs Total`.

Отображение:

- зелёная заливка: подгруппа значимо выше Rest;
- красная заливка: подгруппа значимо ниже Rest;
- без заливки: различие незначимо;
- серая заливка: малая база.

Порог малой базы по умолчанию: `N < 30`, пользователь может изменить его. Это принятое для проекта операционное правило контроля качества, а не универсальная математическая граница применимости статистического метода.

Серая заливка определяется только по невзвешенному `N`, в том числе при включённом весе. Статистический тест проводится, только если невзвешенные базы обеих сравниваемых групп не ниже установленного порога и, при включённом весе, эффективные базы обеих групп также не ниже этого порога. Иными словами, для допуска взвешенного теста проверяется `min(N, n_eff)` каждой группы. Результаты продолжают выводиться, а причина пропуска теста фиксируется в `statistics.txt`; недостаточная эффективная база сама по себе не добавляет серую заливку, если невзвешенный `N` достаточен.

### 9.4. Сравнения внутри баннера

Подгруппы сравниваются между собой внутри логического блока: возраста между возрастами, города между городами и так далее. Результаты попарных сравнений помещаются в примечание к ячейке, чтобы не перегружать топлайн.

Кроме основного уровня доверия может быть задан второй, более мягкий, например 90% при основном 95%. Второй тест при этом не выполняется: для каждого сравнения порог второго уровня выводится из скорректированного alpha основного умножением на (1 − второй уровень) / (1 − основной), поэтому поправка Bonferroni сохраняется. Различие, значимое только на втором уровне, отмечается в примечании к ячейке строчной буквой колонки («Значимо выше при 90%: c — …»); цвет ячейки и стрелка волны по-прежнему следуют основному уровню. Шапка `statistics.txt` и лист `Параметры` называют второй уровень, если он включён.

По настройке отчёта «Общие тесты» для каждого блока баннера выполняется общий тест: хи-квадрат Пирсона без поправки на непрерывность для распределения ответов и Welch ANOVA без предположения равных дисперсий для средних. В книге строка «Хи-квадрат, p» стоит после распределения, строка «Welch ANOVA, p» — после среднего; p-value записывается в первую колонку каждого блока, а полный протокол — в примечание и `statistics.txt`. Тест не выполняется с указанием причины, если база колонки ниже порога, если ожидаемые частоты малы (хотя бы одна меньше 1 или больше 20% ячеек меньше 5), если в колонке нет разброса значений и если данные взвешены: для взвешенного хи-квадрата требуется поправка Rao–Scott, и без неё тест не выводится.

### 9.5. Волны

Пользователь выбирает значения single-переменной волны, которые войдут в отчёт. По умолчанию они располагаются по кодам SAV, но порядок можно изменить вручную; ненужные волны можно исключить.

Поддерживаются два взаимоисключающих режима:

- плавающий тест: каждая включённая волна сравнивается с непосредственно предыдущей в настроенном порядке; у первой волны стрелки нет;
- контрольный тест: каждая включённая волна сравнивается с одной выбранной контрольной; у самой контрольной волны стрелки нет.

Волна может использоваться как обычный блок баннера и как один из двух уровней вложенного блока с демографической переменной. Во вложенном блоке между волнами сравниваются только одинаковые подгруппы: мужчины с мужчинами, женщины с женщинами и так далее.

В минимальной версии волны считаются независимыми выборками. Панельные данные с повторными наблюдениями одних и тех же респондентов и парные тесты не поддерживаются.

Если вопрос отсутствует в сравниваемой волне, группа пуста либо обычная или эффективная база мала, тест не выполняется, а причина фиксируется в `statistics.txt`. Для волн действуют глобальные уровень доверия, Bonferroni, порог малой базы, правила эффективной базы и правило дополнительного знака после запятой, если стандартное округление скрывает значимое различие.

Значимое повышение обозначается зелёной стрелкой вверх, значимое снижение — красной стрелкой вниз. Стрелка ставится в ячейке сравниваемой волны.

### 9.6. Точность расчётов

Числители, знаменатели, средние, дисперсии и статистические тесты рассчитываются по значениям полной точности. Округление применяется только при отображении в Excel и не влияет на решение о статистической значимости. Если два статистически значимо различающихся значения долей после округления до настроенного числа знаков выглядят одинаково, вся соответствующая строка автоматически отображается с одним знаком сверх настроенного, чтобы различие было видно пользователю. Одинаковость проверяется так, как округляет Excel, — половина вверх — для пар, которые читатель сравнивает на листе: двух колонок попарного теста, колонки и её волны, колонки и `Total`. Последняя пара проверяется и при сравнении с остатком: колонки остатка на листе нет, и выделенное число, совпадающее с `Total`, выглядело бы ошибкой. Правило действует для строк долей, включая балансы NPS и CSAT; у средних число знаков настраивается отдельно.

Для каждого выполненного теста вместе с p-value рассчитываются размер наблюдаемого различия и двусторонний доверительный интервал выбранного уровня: разница долей в процентных пунктах для z-теста и разница средних для Welch t-test. При включённой поправке Bonferroni доверительный интервал строится по скорректированному внутри соответствующего семейства уровню alpha.

Для долей проверка гипотезы и доверительный интервал сознательно используют разные оценки дисперсии: тест — объединённую (pooled) при нулевой гипотезе о равенстве долей, интервал — раздельные дисперсии наблюдённых групп. Это принятое решение, а не недоработка: тестовая часть в таком виде совпадает со SPSS `CTABLES /SIGTEST TYPE=PROPS`, а интервал остаётся корректным интервалом для разницы долей. Следствие оговорено явно: у границы принятия решения два способа могут разойтись — тест даёт «незначимо», тогда как интервал не накрывает ноль. Решение о значимости во всех случаях принимается по тесту, а `statistics.txt` предупреждает об этом в шапке. Для Welch t-test расхождения не возникает: тест и интервал используют одну и ту же стандартную ошибку.

Схема сравнения подгрупп настраивается на уровне баннера и по умолчанию равна
`rest`. В этом режиме подгруппа сравнивается с непересекающимся остатком
`Rest = Total − Subgroup`, а Total остаётся описательной колонкой и в тестах не
участвует.

Режим `total` сравнивает подгруппу с самим Total. Это не тест независимых
выборок: подгруппа входит в Total и смещает его к себе, поэтому различие
систематически занижается, а вывод сдвинут в сторону «незначимо». Режим добавлен
осознанно и только ради совпадения с макросами заказчиков, которые считают именно
так; он всегда помечается в `statistics.txt` — и строкой в шапке, и в названии
каждого сравнения.

Отдельного «статистически корректного сравнения с Total» не предусмотрено,
поскольку его не существует: при честном учёте пересечения
`p_subgroup − p_total = (n_rest / n_total) · (p_subgroup − p_rest)`, и стандартная
ошибка масштабируется тем же множителем, поэтому `z` тождественно совпадает с
режимом `rest`. Корректное сравнение части с целым и есть сравнение с остальными.

Статистическая значимость описывает случайную неопределённость только в рамках принятой модели независимых наблюдений и не делает квотную, удобную или иную неслучайную выборку вероятностной либо репрезентативной. Интерпретация результатов должна учитывать дизайн и способ набора выборки.

### 9.7. Файл `statistics.txt`

Для каждого сформированного Excel создаётся отдельный человекочитаемый `statistics.txt` в кодировке UTF-8. В начале файла указываются проект, исходный SAV, дата расчёта, общий фильтр, вес, уровень доверия, состояние Bonferroni и порог малой базы.

Порядок вопросов и строк полностью повторяет Excel. Файл содержит все выполненные сравнения, включая незначимые, а также все пропущенные тесты с явной причиной: малая или недостаточная эффективная база, пустая группа, ожидаемая частота меньше 5 либо иная неприменимость метода. Для каждой группы выводятся буквенный идентификатор и полное название.

Файл не дублирует все описательные показатели топлайна, а содержит только данные, необходимые для аудита тестов:

- для z-теста: точные доли, числители, знаменатели, эффективные базы при весе, все четыре ожидаемые частоты, разницу долей в процентных пунктах, её доверительный интервал, z и p-value;
- для Welch t-test: средние, дисперсии, стандартные ошибки, обычные или эффективные базы, разницу средних, её доверительный интервал, t, степени свободы и p-value;
- при Bonferroni: исходный p-value, скорректированный порог alpha и итоговое решение.

Числовые значения выводятся с точностью до шести знаков после запятой; очень малые p-value обозначаются порогом вида `<0.000001`. Пояснения пишутся по-русски, а стандартные названия методов и обозначения, включая `z-test`, `Welch t-test` и `n_eff`, сохраняются на английском. Для всех взвешенных тестов в файле явно указывается их приближённый характер. Данные отдельных респондентов в файл не попадают.

## 10. Взвешивание

Поддерживаются два режима: применение готовой итоговой переменной веса из SAV и расчёт нового веса по целевым распределениям методом raking/IPF. Рассчитанный вес хранится как производная переменная проекта и не изменяет исходный SAV. В одном отчёте одновременно может действовать только одна переменная веса.

Готовая переменная веса должна быть числовой, положительной и заполненной для всех строк; нули, отрицательные значения и пропуски блокируют её применение. Для расчётов готовый вес внутренне нормализуется к среднему `1`, не изменяя исходную переменную SAV.

Роль `Вес` является необходимым условием выбора: в списке весов показываются только переменные с этой ролью, а любая другая числовая переменная становится доступной лишь после явного действия «объявить весом», которое меняет роль в структуре и убирает переменную из отчёта. Одной роли недостаточно, поэтому перед применением обязательно показывается разбор распределения — минимум, максимум, среднее, доля экстремальных значений, эффективная база Киша и design effect. Вес отклоняется, если доля значений, отличающихся от среднего более чем в 5 раз, превышает 5% или design effect превышает 3. Это блокирующие условия, а не предупреждения: отчёт, посчитанный на таком весе, математически валиден и внешне неотличим от правильного. Проверка выполняется одной функцией для интерфейса, API, проверки конфигурации и сборки, и каждая причина отказа имеет собственный код ошибки.

Для расчёта веса используются single и перекодированные категориальные переменные, но не multiple-response. Целевые распределения вводятся вручную либо импортируются из фиксированного Excel-шаблона приложения. Цели каждой переменной должны давать 100%; сумма в пределах `99,9–100,1` автоматически нормализуется до 100%, большее расхождение считается ошибкой.

Raking начинается с единичных весов; использование готового веса как стартового в минимальной версии не поддерживается. Пропуски в любой переменной взвешивания блокируют расчёт и требуют предварительной перекодировки в отдельную категорию.

Рассчитанный вес нормализуется к среднему `1`, поэтому сумма весов совпадает с исходным N. Если проект содержит волны, raking всегда выполняется отдельно внутри каждой волны с одним и тем же набором целевых распределений; разные цели для отдельных волн и режим совместного расчёта по всему массиву не поддерживаются. Нормализация к среднему `1` также выполняется внутри каждой волны.

Ограничение рассчитанных весов по умолчанию составляет `0,3–3,0`; пользователь может изменить границы или отключить ограничение. После обрезания весов алгоритм повторно подгоняет распределения и ограничения. Расчёт считается сошедшимся, когда максимальное отклонение от цели меньше `0,1` процентного пункта; максимальное число итераций — 500.

Если в выборке отсутствует целевая категория, расчёт блокируется и приложение предлагает объединить категории. Если алгоритм не сходится за 500 итераций, пользователь получает диагностику отклонений и предложение укрупнить категории либо изменить ограничения; такой вес сохранить и использовать в отчёте нельзя.

После расчёта показываются минимум, максимум, среднее и стандартное отклонение веса, эффективная база, design effect, эффективность выборки, а также целевые и фактические распределения до и после взвешивания. Рассчитанный вес можно скачать отдельным Excel-файлом с ID респондента, исходным весом при его наличии и итоговым весом. Если роль ID не назначена, вместо неё используется технический номер строки `1…N`.

В статистических тестах должны корректно учитываться веса и эффективная база; нельзя подставлять взвешенные проценты в формулы с обычным невзвешенным N. Эффективная база рассчитывается по формуле Киша `n_eff = (Σw)² / Σ(w²)` отдельно внутри каждой фактической базы вопроса и каждой сравниваемой подгруппы. Использование `n_eff` в z- и Welch t-тестах является приближением для ситуации, когда приложению доступны итоговые веса, но не полная информация о стратах, кластерах и вероятностях включения. В интерфейсе и `statistics.txt` такие p-value обозначаются как приближённые.

## 11. Корреляции

- Необязательный лист `Correlations` создаётся только при включённом переключателе в настройках отчёта.
- Pearson автоматически рассчитывается для numeric и шкал. Spearman рассчитывается для numeric, шкал, ordinal и ранговых переменных. Номинальные single, multiple и технические переменные исключаются.
- Элементы матрицы считаются отдельными переменными, но визуально группируются под общим названием матричного вопроса.
- На одном листе последовательно выводятся пять числовых таблиц: коэффициенты Pearson, p-value Pearson, коэффициенты Spearman, p-value Spearman и парный N.
- Пропуски исключаются попарно: для каждой пары используются все респонденты, у которых заполнены обе переменные.
- На весь лист действует общий фильтр отчёта. Индивидуальные пользовательские базы вопросов не применяются к корреляциям.
- При включённом весе рассчитываются взвешенный Pearson через взвешенную ковариацию и Spearman через корреляцию взвешенных рангов. Приближённый p-value определяется через эффективную базу Киша по статистике `t = r × √((n_eff − 2) / (1 − r²))`; для Spearman формула применяется после построения взвешенных рангов. В заголовке листа явно указывается приближённый характер p-value взвешенных корреляций.
- Глобальная настройка Bonferroni на корреляции не распространяется; отдельного переключателя коррекции для корреляционного листа нет.
- Положительные значимые коэффициенты выделяются зелёным, отрицательные — красным. Насыщенность имеет три уровня для `p < 0,05`, `p < 0,01` и `p < 0,001`; незначимые коэффициенты остаются без заливки.
- Если невзвешенная парная база ниже 30, коэффициент показывается серым. P-value и цвет значимости не рассчитываются, если невзвешенная парная база или, при включённом весе, эффективная парная база ниже 30; недостаточная эффективная база сама по себе не добавляет серую заливку.
- На диагонали таблицы коэффициентов показывается `1`; p-value и парный N на диагонали не выводятся.
- Коэффициенты отображаются с тремя знаками после запятой, p-value — с шестью; в ячейках сохраняется полная числовая точность.
- Автоматически исключаются ID, вес, волна, технические, nominal и multiple, а также константы и переменные с валидной базой ниже 30. Если после этого остаётся больше 100 переменных, в матрицу включаются первые 100 по порядку SAV. Интерфейс показывает исключённые переменные и позволяет вручную заменить ими любую из включённых, сохраняя лимит 100.

Получен файл `Topline_Шаблон.xlsx`. Он задаёт базовую визуальную иерархию, но не считается окончательным шаблоном всех будущих листов и методов.

Зафиксированные элементы:

- в исходном эталоне листы назывались `Содержание`, `Total Main`, `Topline filter`; итоговые имена продукта определены в разделе 8.2;

- первый столбец содержит структуру вопроса и варианты ответа;
- блок вопроса состоит из кода, полного текста вопроса, пояснения/текста шкалы и строк результатов; отдельной сущности `Раздел` в продукте нет;
- содержание разделяется по целевым листам и содержит ссылки на отдельные вопросы;

- доли отображаются целыми числами без знака `%`, при этом в ячейках должны храниться числовые значения, а не текст.
