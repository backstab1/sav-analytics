## 3. Как читать оценки

Оценки даны в **человеко-неделях для одного разработчика, знакомого с кодом**.
Календарные даты не проставлены сознательно: они зависят от числа занятых людей и
доли их занятости, а эти данные в проекте не зафиксированы. Чтобы получить даты,
умножьте на свою фактическую загрузку.

Оценки могут сдвинуть: интеграция с конкретным корпоративным SSO, миграция уже
накопленных проектов и отсутствие lock-файла, из-за которого обновление
зависимости способно изменить расчёт.

## 4. Трек A — внутренний запуск для своей команды

Цель: приложение доступно нескольким аналитикам внутри периметра.

| № | Шаг | Оценка | Зачем |
| --- | --- | --- | --- |
| 1 | Аутентификация, владелец проекта, роли | 2–3 нед | Блокер. Без него любое сетевое размещение открывает исследовательские данные |
| 2 | HTTPS и reverse proxy, non-root в Docker, `HEALTHCHECK` | 3–5 дн | Условие выставления наружу |
| 3 | CI: pytest, ruff, coverage, сборка образа | 2–3 дн | Самое дешёвое в списке, ловит регрессии сразу |
| 4 | Структурное логирование, ID запроса и задачи | 2–3 дн | Иначе разбор инцидента вслепую |
| 5 | Резервное копирование с проверенным восстановлением | 3–5 дн | Файловое хранилище без бэкапа означает потерю проектов |
| 6 | E2E smoke: загрузка, настройка, выгрузка XLSX | 3–5 дн | Юнит-тесты не покрывают связку интерфейса и API |
| 7 | Lock-файл и расширение настроек | 1–2 дн | Воспроизводимость сборки |
| | **Итого** | **5–7 недель** | |

На этом треке файловое хранилище и внутрипроцессная очередь сохраняются. Принятые
ограничения, которые нужно зафиксировать письменно для пользователей:

- при перезапуске теряется статус текущей задачи; пересчёт дешёвый благодаря кэшу;
- нельзя запустить второй экземпляр API — задачи продублируются;
- тяжёлый отчёт блокирует очередь целиком, поскольку worker один.

## 6. Аналитические пробелы

Запуск не блокируют.

| Функция | Оценка | Комментарий |
| --- | --- | --- |
| Корреляции | 2–3 нед | Единственный крупный разрыв с требованиями: пять таблиц, взвешенные Pearson и Spearman, лимит 100 переменных с ручной заменой |
| Ручной редактор структуры | 1,5–2 нед | Создание логического вопроса, объединение и разгруппировка |
| Доработка волн | 1,5–2 нед | Выбор и порядок волн, raking внутри волн, цели по проектным перекодировкам |

CBC conjoint, MaxDiff и конструктор CSI отнесены самими требованиями (раздел 12) к
отложенным модулям. Не начинать до подтверждения спроса и согласования методики.

## 7. Рекомендуемый порядок

1. **Шаг 1 — аутентификация, прежде всего остального.** Приложение уже работает с
   реальными данными респондентов. Пока нет разграничения доступа, размещение за
   пределами машины разработчика означает утечку. Остальное можно доделывать после
   запуска, это — нет.
2. **Шаги 3 и 6 — CI и e2e.** Дёшевы и защищают всю последующую работу.
3. **Остаток трека A** в любом удобном порядке.
4. **Корреляции — после запуска.** Отсутствие корреляций не мешает выпускать
   топлайны; отсутствие авторизации мешает работать вообще.

## 8. Известные технические долги

Обнаружены при работе над кодом, в план выше не входят из-за малого объёма.

- Доверительный интервал теста долей строится по раздельным дисперсиям, тогда как
  сам тест использует объединённую; у границы принятия решения это даёт видимое
  противоречие в аудите. Подробности и варианты решения — в
  [spss-conformance.md](spss-conformance.md), раздел 4.4.
- `repository.py`: четыре сущности с почти одинаковым набором CRUD-методов, около
  250 строк дублирования.
- `app.js`: 2182 строки одним файлом, 10 глобальных переменных; логика «скрыть
  редакторы и обнулить идентификаторы» повторяется в десяти функциях.
- Фронтенд запрашивает предпросмотр даже для технических и исключённых вопросов,
  получая в ответ ошибку 422.
